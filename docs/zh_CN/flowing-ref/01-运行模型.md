# 01 · 消息驱动的智能体：运行模型

> 本篇回答：**系统怎么跑起来？**
> 读完你能：配好模型接入、拉起一个 flowing 子项目、完成一次对话，
> 并理解消息如何驱动回合。

## 1.1 一个 flowing 子项目由什么组成

flowing 应用以子项目为装配单位。最小问答示例由以下五个文件组成：

| 文件名 | 用途 |
|---|---|
| `main.py` | 入口；`launch` 导入它并等待 `main()` 返回 Runtime。 |
| `root.fya` | 根 Agent 的声明式定义。 |
| `providers.yaml` | Provider 适配器、端点和环境变量凭证占位符。 |
| `models.yaml` | 模型到 Provider 条目的绑定。 |
| `model-tags.yaml` | 标签到模型条目的映射。 |

`root.fya` 是声明式 Agent 定义（`.fya` = flowing agent/tool 声明文件）：

```yaml
description: 最小问答助手
model_tag: default
---
$system_prompt:
你是一个简洁的中文助手，回答控制在三句话以内。
```

YAML 头部声明元信息，`---` 分隔后的 `$system_prompt:` 具名块是系统提示词
（唯一必填项）。没有任何 Python 代码——这就是一个有完整行为能力的 Agent。

`main.py` 是子项目入口，负责**组装**：构造 Runtime、登记模型来源、挂载根
Agent：

```python
"""hello 子项目入口：launch 会导入本文件并等待 main()。"""

from flowing import Runtime

async def main(resume: str | None = None) -> Runtime:
    runtime = Runtime(persist_dir="@/.flowing")
    # runtime.set_providers("@/providers.yaml")
    # runtime.set_models("@/models.yaml")
    runtime.set_model_tags("@/model-tags.yaml")
    if resume is not None:
        await runtime.recover_agent(resume)   # 恢复既有 agent
    else:
        # 固定 agent_id → 幂等挂载：第二次启动走恢复，“同一个根回来了”
        await runtime.mount("@/root.fya", agent_id="agent-main")
    return runtime
```

注意两件事：

- **新建还是恢复，是 `main()` 的策略，不是框架的参数**。框架不认识
  `--resume`；你的 `main()` 自行决定（这里用 `resume` 参数表达）。
- 根 Agent 用 `mount()` 挂载；`agent_id` 固定时第二次启动自动走恢复管线
  （幂等挂载），`None` 则每次新建。

## 1.2 模型接入：三个 yaml 与 model_tag 两跳解析

智能体系统跑不起来的第一大原因是模型没配对。flowing 把模型接入拆成三个
文件，职责单一、可独立替换：

```yaml
# providers.yaml —— provider 条目：一个条目 = 一个 API key 身份
deepseek:
  adapter: deepseek
  base_url: https://api.deepseek.com
  api_key: "{{env.DEEPSEEK_API_KEY}}"   # 凭证经环境变量注入，不硬编码
openrouter:
  adapter: openrouter
  base_url: https://openrouter.ai/api/v1
  api_key: "{{env.OPENROUTER_API_KEY}}"
```

```yaml
# models.yaml —— 模型条目：一个条目 = 一个具体模型，通过 provider 字段绑定 provider 条目
deepseek-flash:
  provider: deepseek
  model: deepseek-v4-flash
openrouter-gpt-6-luna:
  provider: openrouter
  model: openai/gpt-6-luna
  "reasoning.effort": high
```

```yaml
# model-tags.yaml —— 标签 → 模型条目名映射（单值，无回退链）
tags:
  default: deepseek-flash
  luna: openrouter-gpt-6-luna
```

Agent 声明里的 `model_tag: default` 如何变成一次真实的 API 调用？
**两跳解析**：

```
model_tag("default") ──① model-tags.yaml──▶ 条目名("deepseek-flash")
                     ──② models.yaml──────▶ ModelConfig(provider=deepseek,
                                             model=deepseek-v4-flash)
model_tag("luna")    ──① model-tags.yaml──▶ 条目名("openrouter-gpt-6-luna")
                     ──② models.yaml──────▶ ModelConfig(provider=openrouter,
                                             model=openai/gpt-6-luna,
                                             extra={"reasoning.effort": "high"})
```

三个文件分别声明接入身份、模型及标签映射：`models.yaml` 中的 `provider`
选择 `providers.yaml` 的条目，`model` 是发给该 provider 的模型 ID；标签只指向
`models.yaml` 的条目名。当前 `default` 仍使用 DeepSeek。将 Agent 的
`model_tag` 改为 `luna`，就会经 OpenRouter 调用 `openai/gpt-6-luna`；需要
设置 `OPENROUTER_API_KEY`。`"reasoning.effort": high` 是该模型条目的字面扩展键，
只随 GPT-6 Luna 传给 OpenRouter；DeepSeek 条目没有该设置。

规则要点：标签未定义时回退 `default` 标签；`default` 也未定义 → 报错，
**不静默降级**。`{{env.X}}` 在条目加载期替换，缺失环境变量替换为空串并
`warnings.warn` 告警、**加载不中断**（配多个条目只用一个时，其余条目的
环境变量不必齐备；缺失凭证的实际后果——如 401——在该条目首次调用时经
`on_provider_error` 暴露）。来源路径默认在 `$FLOWING_CONFIG_HOME/`
（可被环境变量或 `set_providers` 等编程覆盖，见第 04 篇 §4.6）。

## 1.3 launch 与 Runtime：对象图根

`flowing.launch(path, **kwargs)` 是创建 Runtime 的**唯一入口**。它做的事
很薄：登记 `@` 项目根上下文（`@/` 路径前缀的解析基准，按 asyncio Task
隔离）→ import 子项目 `main.py` → `await main(**kwargs)` → 复位上下文。
不解析配置、不认识插件、不开端口——这些都在 `main()` 或更外层。

框架自带的 **REPL**（`repl` 子命令）是建立在 `launch`
之上的最小交互观察窗口——正好用来把第一个示例跑起来看效果：非 `/`
输入经 `query()` 投递给绑定的 Agent，`/xxx` 是控制命令（不进消息流）：

```console
$ flowing repl .
(agent-main)>>> 用一句话介绍你自己。
我是一个简洁的中文问答助手，回答会尽量控制在三句话以内。
[thinking] (reasoning trace omitted)
我是一个简洁的中文问答助手，回答会尽量控制在三句话以内。
(agent-main)>>> /exit
```

（编程式 `await flowing.launch(...)` 是嵌入宿主应用时的入口，见第 04 篇
§4.5。）

Runtime 是**对象图根**：持有全部 Agent 节点（`_nodes`）、全局工具注册表
（`tool_registry`）与 Agent 类型注册表（`agent_registry`）、
agent 池、provide 存储（注入链终点）。它的 `node_id` 固定为
`"runtime-0"`；根 Agent 的 `_parent_id` 指向它——多智能体系统的拓扑就是
一棵以 Runtime 为根的树（见第 03 篇）。

两个常用语义：

- **`await runtime`** 阻塞至 `shutdown()`——CLI/嵌入方用它保持进程存活；
- **`shutdown()`** 递归 destroy 全部 Agent（排空各自持久化后端）→ 插件
  收尾 → 关全局状态视图。持久化是 write-behind（提交只排队），不
  `shutdown()` 直接退进程会丢尾部记录。REPL 的 `/exit`（或 Ctrl-D）走
  的就是这条路径。

## 1.4 Agent：队列、工作循环与逻辑 Turn

每个 Agent 实例拥有：一条**优先级消息队列**、一个**常驻工作循环 Task**、
一棵**消息级树**（第 02 篇）、一组实例级钩子（第 04 篇）。创建即启动
工作循环，此后一切行为都由消息驱动。

用户输入、模型响应、工具结果、外部事件、子 Agent 回执，在框架里统一
表示为 `Message`。**回合只能由消息触发**：cron 到点、异步工具完成、
子 Agent 交卷，都是先变成一条消息入队，再被工作循环消费；连导向与
打断也是带优先级的消息（STEER / INTERRUPT），不是带外信号。

**消息进**——三个入口，按是否需要结果选择：

```python
result = await agent.query("帮我查订单 4521")   # 等回合产物（TurnResult）
mid = await agent.message("稍后提醒我喝水")      # fire-and-forget，只要消息 id
await agent.steer("预算上限改为 500")            # 回合进行中导向（STEER 优先级）
```

**回合出**——工作循环串行消费队列，每条（批）消息驱动一个**逻辑 Turn**：
组装上下文 → 调模型 → 可能执行工具 → 直到响应 `finish=True` 收尾。
`query()` 等到的是 `TurnResult`：

```python
result.status       # "completed" / "blocked" / "cancelled" / "error"
result.final_text   # 本回合最后一条 PROVIDER 消息的文本
result.token_usage  # 本回合聚合 token 用量
```

四种结局**都会** resolve 给等待者——崩溃、取消、`destroy()` 都不会让
`query()` 的调用方挂起。

**死锁禁令**（新手最常踩的坑）：在当前回合的调用栈内（任何钩子、工具
`execute` 内）`await query()` 必死锁——回合收尾要等钩子返回，钩子要等
下一回合，下一回合要等当前回合收尾。跨 Agent 等待成环（A 等 B、B 等 A）
同理。回合内需要驱动，用 `steer()`（当轮上下文可见、不打断），不要
`query()`。

## 1.5 创建管线与 setup()

Agent 实例不直接构造，唯一创建路径是 `Runtime.create_agent`（`mount` /
`create_subagent` 都委托它）。管线关键步骤：`__new__` 预绑身份 →
`__init__` 同步骨架 → 写 `meta.json` → `before_create` 钩子 →
**`setup(**kwargs)`** → PENDING 检查 → 模型解析 → 注册 → 启动工作循环。

`setup()` 是你写装配代码的地方（类属性管声明，setup 管装配）：

```python
async def setup(self, user_id: int, locale: str = "zh"):
    self.user_id = user_id          # 状态赋值（运行期配置，不落盘）
    self.locale = locale
    self.add_tool("make-payment")   # 能力绑定
    self.provide("user_id", user_id)  # 敏感值走注入通道（第 04 篇）
```

约束：`setup()` 要**轻量**（网络/重 IO 放工具里）；`**kwargs` 会持久化进
`meta.json` 并在恢复时透传，必须 JSON 可序列化——它是 Agent 身份的一部分。

恢复管线（`recover_agent`）同构，多一步重放 session 日志，且触发的是
`before_recover` / `after_recover` 钩子对——与 create 钩子对**完全独立**。
恢复后：消息历史、状态袋、child_ids 都在；进行中的 Turn 不续跑。

## 1.6 完整示例：问答 Agent

§1.1–1.2 已列出运行本例所需的 `main.py`、`root.fya` 和三个模型配置文件
的完整内容。运行环境需要 Python 3.13 或更高版本、已安装的 Flowing，以及
你自己的 DeepSeek API 凭证；凭证仅通过环境变量提供：

```console
$ export DEEPSEEK_API_KEY='<your DeepSeek API key>'
$ flowing repl .
```

在包含上述五个内联文件的当前工作目录中运行命令，然后输入示例问题：

```console
(agent-main)>>> 用一句话介绍你自己。
我是一个简洁的中文问答助手，回答会尽量控制在三句话以内。
[thinking] (reasoning trace omitted)
我是一个简洁的中文问答助手，回答会尽量控制在三句话以内。
(agent-main)>>> /exit
```

输入由 REPL 通过 `query()` 投递，回答内容由模型生成，措辞可能不同；
`/exit` 触发 `shutdown()` 后退出。再次启动时，固定 `agent_id` 使 REPL
绑定回同一个根 Agent，并进入恢复管线。

一条 USER 消息的完整旅程：`query()` 打包入队 → 工作循环出队开 Turn →
组装上下文（system_prompt + 消息路径 + 工具声明）→ Provider 响应 →
响应消息挂树落盘 → 收尾组装 `TurnResult` → resolve 给等待者。

## 1.7 小结

本篇要点：

1. 子项目 = `main.py`（组装策略）+ `.fya`（Agent 声明）+ 模型三文件；
2. `launch` 唯一入口，Runtime 是对象图根，`main()` 决定新建/恢复；
3. Agent = 队列 + 工作循环；`query` 等 TurnResult，四结局不挂起；
4. 回合栈内禁 `query`，用 `steer`。
