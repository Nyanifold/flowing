## 中文

### Peers 插件：同一 Runtime 内的定向 Agent 交互

新增 `PeersPlugin`，注册 `query-peer`、`message-peer` 与 `steer-peer` 三件工具，并提供统一的 peer 路由服务。Agent 在 `.fya` 的 `peers:` 字段声明可联系的 Agent ID 与描述，在 `tools:` 字段显式绑定模型需要使用的工具，并在 `setup()` 中调用 `use_peers(self)` 将目录注入系统提示。

三个工具都只向一个已声明 peer 路由消息。`query-peer` 立即返回 pending 收据，目标 Agent 的回合结果稍后作为 EVENT 到达；`message-peer` 入队 PEER 消息后返回消息 ID，不等待目标回合；`steer-peer` 以 STEER 优先级入队并返回消息 ID。目标从调用方所属 Runtime 按精确 ID 解析，未实例化但仍在 Agent 池中的目标会由 Runtime 恢复。

**用法：** 在挂载 Agent 前安装插件，并在各 Agent 的 `setup()` 中调用 Composable：

```python
runtime.install(PeersPlugin())
```

Agent 声明 `peers:` 目录、通过 `tools:` 绑定所需工具，并在 `$script` 中调用 `use_peers(self)`。安装插件本身不会让工具对所有 Agent 可见；peer 交互消息进入目标 Agent 的消息队列和消息树，双方的私有历史不会自动复制。

### REPL 异步提示符

交互式 REPL 在等待用户输入时保持 asyncio 事件循环运行。后台 Agent 可继续处理排队消息，Peer 对话也能在提示符空闲时推进；后台输出会保留可见提示符。TTY 输入继续支持方向键、行编辑、会话历史与 slash-command 补全。

**用法：** 按原有方式启动交互式 REPL；Agent 收到后台消息后会在提示符等待期间继续工作。

```console
$ flowing repl .
```

### REPL 启动时显示 Agent 名录

交互式 REPL 在启动绑定完成后显示 Runtime 池名录中的全部 Agent，包括休眠记录。每条记录单独占一行，Agent ID、最后回复前缀和最后修改时间以制表符分隔，并按显示宽度填充对齐；名录为空时显示 `(no agent records)`。

**用法：** 启动 REPL 后即可查看 Agent 名录；休眠记录可用 `/agent <agent_id>` 恢复并绑定。

### 独立配置命令 `flowing-config providers`

新增独立的 `flowing-config` 命令及首个资源子命令 `providers`，提供 Provider 条目的交互式添加、列表和删除。配置操作保留原始 YAML 注释、顺序、未知字段和环境变量模板；敏感字段输入时以明文显示，列表会遮蔽敏感值，写入在新建 Runtime 后生效。Provider 字段由 adapter 元数据提供，命令不启动 Runtime 或访问模型服务。

命令帮助、交互提示和状态输出均使用英文。

`flowing-config -h` 提供命令总览，并将 `providers` 列为子命令；使用
`flowing-config <subcommand> -h` 查看子命令的详细帮助。

添加 Provider 时，类别提示支持 Tab 补全。唯一匹配时按一次 Tab 即可补全；使用 editline 后端时，多个候选需再次按 Tab 才显示列表。GNU Readline 后端会在第一次 Tab 时显示多个候选。

**用法：**

```console
$ flowing-config providers add
$ flowing-config providers list
$ flowing-config providers delete
```

省略路径时，在路径提示处直接回车即可使用 Runtime 的默认用户级配置路径。添加时输入 `env.API_KEY` 会保存为 `{{env.API_KEY}}`；列表保留模板文本；删除需明确输入 `y` 确认。

### 教程中的全局 Provider 复用说明

入门教程、详细教程和精简参考的首篇说明可将 Provider 配置写入全局用户级文件，后续项目由 Runtime 自动读取，不必重复创建项目级 `providers.yaml` 或调用 `set_providers()`。

**用法：** 首次运行 `flowing-config providers add` 并选择默认用户级路径；后续示例在 `models.yaml` 中引用已有条目名。

### REPL 消息链完整查看

`/messages` 支持 `v` / `verbose` 参数。运行 `/messages v` 可按消息 ID 和类型查看当前消息链，并完整显示文本、思考过程、工具调用名称与参数、工具结果和结构数据；媒体块显示类型、名称、MIME 和 base64 载荷长度。普通模式为各类内容块提供摘要：思考与工具调用会缩略，结构块显示 JSON 预览，媒体块显示元数据和载荷长度；工具结果在渲染后不超过 500 个字符时完整显示，超出时截断并标注省略长度。

**用法：**

```text
/messages
/messages v
/messages verbose
```

## English

### Peers plugin: directed agent interaction within one Runtime

Adds `PeersPlugin`, which registers the `query-peer`, `message-peer`, and `steer-peer` tools and provides a shared peer router. An Agent declares allowed Agent IDs and descriptions under `.fya`'s `peers:` field, explicitly binds the tools it needs under `tools:`, and calls `use_peers(self)` from `setup()` to add the catalog to its system prompt.

Each tool routes to one declared peer. `query-peer` returns a pending receipt immediately and later delivers the target Agent's turn result as an EVENT; `message-peer` queues a PEER message and returns its message ID without waiting for the target turn; `steer-peer` queues a message at STEER priority and returns its message ID. The target is resolved by exact ID in the caller's Runtime. If it is in the Agent pool but has no live instance, the Runtime recovers it.

**Usage:** Install the plugin before mounting Agents, then enable the Composable from each Agent's `setup()`:

```python
runtime.install(PeersPlugin())
```

Declare the `peers:` catalog, bind the desired tools under `tools:`, and call `use_peers(self)` from `$script`. Installing the plugin does not make its tools visible to every Agent. Peer messages enter the target Agent's message queue and message tree; the Agents' private histories are not copied automatically.

### Asynchronous REPL prompt

The interactive REPL keeps the asyncio event loop running while waiting for user input. Background Agents can continue processing queued messages, and peer conversations can progress while the prompt is idle; concurrent output preserves the visible prompt. TTY input retains arrow-key navigation, line editing, session history, and slash-command completion.

**Usage:** Start the interactive REPL as usual; Agents continue working on background messages while it waits at the prompt.

```console
$ flowing repl .
```

### Agent directory at REPL startup

After resolving its startup binding, the interactive REPL prints every Agent in the Runtime pool, including inactive records. Each record occupies one line with the Agent ID, last-reply preview, and modification time separated by tabs and padded to align by display width. An empty pool is shown as `(no agent records)`.

**Usage:** View the Agent directory when the REPL starts; restore and bind an inactive record with `/agent <agent_id>`.

### Standalone configuration command: `flowing-config providers`

Adds the standalone `flowing-config` command and its first resource subcommand, `providers`, for interactively adding, listing, and deleting Provider entries. Configuration operations preserve raw YAML comments, ordering, unknown fields, and environment-variable templates; sensitive fields are shown as plain text while entered, list output masks sensitive values, and changes apply to newly constructed Runtime instances. Adapter metadata supplies the Provider fields. The command does not start a Runtime or contact a model service.

The command's help, prompts, and status messages are in English.

`flowing-config -h` provides an overview and lists `providers` as a subcommand.
Run `flowing-config <subcommand> -h` for detailed subcommand help.

When adding a Provider, the adapter prompt supports Tab completion. Press Tab once to complete a unique match. With the editline backend, press Tab again to display multiple matches; GNU Readline displays them on the first Tab.

**Usage:**

```console
$ flowing-config providers add
$ flowing-config providers list
$ flowing-config providers delete
```

When no path is supplied, press Enter at the path prompt to use the Runtime's default user-level configuration path. Entering `env.API_KEY` while adding an entry saves it as `{{env.API_KEY}}`; list output preserves the template text; deletion requires an explicit `y`.

### Tutorial guidance for shared global Providers

The first chapter of the beginner tutorial, detailed tutorial, and concise reference explains that a Provider can be stored in the global user-level file and loaded automatically by later projects, without recreating a project-level `providers.yaml` or calling `set_providers()`.

**Usage:** Run `flowing-config providers add` once and choose the default user-level path; later examples reference the existing entry name from `models.yaml`.

### Full message-chain view in the REPL

`/messages` accepts the `v` / `verbose` argument. Run `/messages v` to display the current message chain with message IDs and kinds as separators, and show all text, reasoning, tool-call names and arguments, tool results, and structured data in full. Media blocks show their type, name, MIME type, and base64 payload length. Normal mode summarizes each content-block type: thinking and tool calls are abbreviated, structured data gets a folded JSON preview, and media shows its metadata and payload length. Tool results are shown in full when their rendered content is at most 500 characters and are truncated above that limit with the omitted length indicated.

**Usage:**

```text
/messages
/messages v
/messages verbose
```
