## 中文

### 独立配置命令 `flowing-config providers`

新增独立的 `flowing-config` 命令及首个资源子命令 `providers`，提供 Provider 条目的交互式添加、列表和删除。配置操作保留原始 YAML 注释、顺序、未知字段和环境变量模板；列表会遮蔽敏感值，写入在新建 Runtime 后生效。Provider 字段由 adapter 元数据提供，命令不启动 Runtime 或访问模型服务。

命令帮助、交互提示和状态输出均使用英文。

**用法：**

```console
$ flowing-config providers add
$ flowing-config providers list
$ flowing-config providers delete
```

省略路径时，在路径提示处直接回车即可使用 Runtime 的默认用户级配置路径。添加时输入 `env.API_KEY` 会保存为 `{{env.API_KEY}}`；列表保留模板文本；删除需明确输入 `y` 确认。

### 教程中的全局 Provider 复用说明

入门教程、详细教程和精简参考的首篇说明可将 Provider 配置写入全局用户级文件，后续项目由 Runtime 自动读取，不必重复创建项目级 `providers.yaml` 或调用 `set_providers()`。

**用法：** 首次运行 `flowing-config providers add` 并选择默认用户级路径；后续示例在 `models.yaml` 中引用已有条目名。

## English

### Standalone configuration command: `flowing-config providers`

Adds the standalone `flowing-config` command and its first resource subcommand, `providers`, for interactively adding, listing, and deleting Provider entries. Configuration operations preserve raw YAML comments, ordering, unknown fields, and environment-variable templates; list output masks sensitive values, and changes apply to newly constructed Runtime instances. Adapter metadata supplies the Provider fields. The command does not start a Runtime or contact a model service.

The command's help, prompts, and status messages are in English.

**Usage:**

```console
$ flowing-config providers add
$ flowing-config providers list
$ flowing-config providers delete
```

When no path is supplied, press Enter at the path prompt to use the Runtime's default user-level configuration path. Entering `env.API_KEY` while adding an entry saves it as `{{env.API_KEY}}`; list output preserves the template text; deletion requires an explicit `y`.

### Tutorial guidance for shared global Providers

The first chapter of the beginner tutorial, detailed tutorial, and concise reference explains that a Provider can be stored in the global user-level file and loaded automatically by later projects, without recreating a project-level `providers.yaml` or calling `set_providers()`.

**Usage:** Run `flowing-config providers add` once and choose the default user-level path; later examples reference the existing entry name from `models.yaml`.
